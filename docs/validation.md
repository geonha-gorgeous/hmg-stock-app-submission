## 브라우저·에뮬레이터 확인

11월 4일 화면 재구성에서는 CSS 기준 1280×720과 1024×600의 주간·야간, 주차·간소화 화면을 확인했습니다. 선택 종목과 네 개 관심종목, 브리핑·매수·매도 버튼이 주요 화면 안에 표시됩니다. 1280×720의 분할 주행 화면에서도 두 영역을 유지했습니다. 400×844에서는 하단 메뉴와 가로 넘침이 없는 것을 확인했습니다.

방향키의 매수 버튼→선택 종목 이동, 주문창 종료 후 초점 복귀, 빠른 실행의 종목·수량 입력, 모의 매수 2주 접수·취소, 현대차 1주 매도 접수·체결과 주문내역 반영을 확인했습니다. 브리핑 시작 상태와 탭 전환 시 재생 중지, 빈 관심종목 복구도 점검했습니다. 브라우저 콘솔의 경고·오류는 없었습니다. 실제 차량에서 시선 이동 시간이나 조작 성공률을 측정한 결과는 아닙니다.

아래는 화면 재구성 전의 검증 기록입니다.

11월 4일 UI 변경본에서 빠른 실행으로 수량 2주 입력, 수량 버튼 변경, 모의 접수·취소, 키보드 수량 1주→2주 편집·종료와 원래 버튼으로 초점 복귀를 확인했습니다. 주간·야간·간소화 보기, 차량 정보 미수신과 빈 관심종목 화면을 점검했습니다. 900×600에서는 주문창, 400×844에서는 빠른 실행과 하단 메뉴를 확인했으며 가로 넘침과 브라우저 콘솔 오류를 발견하지 못했습니다.

2026-11-03의 브라우저 검증에서 종목 선택, 영역 간 방향 이동, 수량 1주→2주 편집과 종료, 모의 주문 접수·취소, 팝업 종료 후 초점 복귀를 확인했습니다. 900×600·400×844·1280×800 화면과 주간·야간·분할 상태를 점검했습니다. 현재 UI 캡처는 [관심종목 화면](images/watchlist.jpg), [수량 2주 주문창](images/order.jpg)에 있습니다.

일반 Pixel API 36 에뮬레이터에서는 APK 설치·기동, 예시 데이터, 외부 요청 차단, 표준 키와 합성 회전 입력, 2주 주문, 하위 Back 닫기와 최상위 Back 숨기기를 확인했습니다. 앱을 숨긴 뒤 프로세스 유지도 확인했습니다. 검증 명령은 `cd android` 후 `node scripts/verify-emulator.mjs emulator-5554 --journey`입니다. 이 명령은 해당 에뮬레이터 앱의 예시 주문 상태를 초기화합니다.

이번 APK는 웹 빌드 결과 98개 파일이 APK 내부 자산과 바이트 단위로 일치하는 것을 확인했으며 라이선스 파일을 포함합니다. Gradle 9.3.1 빌드는 통과했고 향후 Gradle 10 관련 deprecated feature 경고가 있습니다.

2026-11-15 독립 브라우저 검수에서 1280×720·1024×600·400×844 가로 넘침, 2주 매수 접수·취소, 1주 매도 체결·보유 수량 반영, 빈 관심종목 복구, 방향 입력·수량 편집·초점 복귀를 확인했습니다. 테스트한 경로의 페이지·콘솔 오류는 0건입니다. 음성 엔진은 모의 처리해 재생 시작과 탭 전환 시 중지만 확인했습니다.

같은 날 API 36 에뮬레이터에 debug APK를 설치하고 `verify-emulator.mjs --journey`를 실행했습니다. 외부 요청·이동 차단, 표준 키·합성 회전 전달, 최초 종목 초점, 2주 주문 접수, 하위 Back 닫기와 최상위 Back 숨기기, 프로세스 유지를 확인했습니다. 이전 CSS 선택자를 사용하던 검증 스크립트는 현재 앱의 `data-ccp-target="order-buy"`를 사용하도록 수정했습니다.

현재 소스로 빌드한 debug APK의 SHA-256은 저장된 파일과 일치합니다. release 구성은 별도 RSA 3072비트 키로 서명했습니다. `apksigner verify` 통과, API 36 에뮬레이터 설치·기동·화면 표시를 확인했으며 `DEBUGGABLE` 플래그가 없습니다. release APK의 웹 자산 98개는 웹 빌드와 일치합니다. release에서 DevTools를 켜지 않았으므로 앞의 자동 DOM 주문 검증은 debug APK 결과입니다.

- 한국투자증권·키움의 실제 키 인증·조회·모의 주문·취소
